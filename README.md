## Архитектура и структура проекта

- **Interfaces**  
  Содержит контракты для различных компонентов:
  - **IAlive.cs** – Интерфейс для живых сущностей. Объявляет свойства `Name` и `Food`.
  - **IInventory.cs** – Интерфейс для инвентаризуемых объектов. Объявляет свойства `Number` и `Name`.
  - **IZoo.cs** – Интерфейс для управления зоопарком.
  - **IVeterinaryClinic.cs** – Интерфейс для проверки состояния здоровья животных.

- **Things**  
  Содержит реализацию для инвентаризуемых вещей:
  - **Thing.cs** – Базовый класс для вещей, реализует `IInventory`.
  - **Computer.cs** – Класс, представляющий компьютер как инвентаризуемый объект.
  - **Table.cs** – Класс, представляющий стол как инвентаризуемый объект.

- **Models**  
  Содержит реализацию доменной модели для животных:
  - **Animal.cs** – Базовый класс для животных, реализует `IAlive`.
  - **Monkey.cs** – Класс, представляющий обезьяну.
  - **Rabbit.cs** – Класс, представляющий кролика (с дополнительным свойством доброты).
  - **Tiger.cs** – Класс, представляющий тигра.
  - **Wolf.cs** – Класс, представляющий волка.
  - **Herbo.cs** – Класс для травоядных животных с дополнительными характеристиками.
  - **Predator.cs** – Класс для хищных животных.
  - **InventoryItem.cs** – Базовый класс для общих свойств инвентаризации, если требуется его использовать совместно с другими моделями.

- **Services**  
  Содержит бизнес-логику приложения:
  - **Zoo.cs** – Класс, управляющий списком животных и вещей.
  - **VeterinaryClinic.cs** – Класс, реализующий логику проверки здоровья животных.

- **Actions**
  Содержит логику действий
   
- **Program.cs**  
  Консольное приложение с точкой входа, настройкой DI-контейнера и основной логикой запуска.

- **Tests** (проект `ТкачукАС_HW1.Tests`)  
  Содержит тесты, покрывающие функциональность приложения с использованием xUnit:
  - **AnimalTests.cs** – Тесты для проверки корректности работы классов животных.
  - **ThingTests.cs** – Тесты для проверки корректности работы классов вещей.
  - **VeterinaryClinicTests.cs** – Тесты для проверки логики работы ветеринарной клиники.
  - **ZooTests.cs** – Тесты для проверки работы зоопарка (добавление животных и вещей, вычисление суммарного потребления еды, фильтрация интерактивных животных).

## Применение принципов SOLID

- **Single Responsibility:**  
  Каждый класс отвечает за свою конкретную задачу:  
  - `Zoo` управляет животными и вещами.  
  - `VeterinaryClinic` занимается проверкой здоровья.  
  - Конкретные модели (например, `Monkey`, `Rabbit`) содержат только данные и поведение, связанные с представлением сущности.

- **Open/Closed:**  
  Классы спроектированы так, чтобы их можно было расширять без изменения существующего кода. Например, для добавления нового типа животного достаточно создать новый класс, наследующий от `Animal`.

- **Liskov Substitution:**  
  Все подклассы, наследующие от базовых классов (например, `Animal`), могут использоваться везде, где ожидается базовый тип, поскольку они реализуют необходимые контракты (например, `IAlive`).

- **Interface Segregation:**  
  Интерфейсы разделены по функциональности. Например, класс, представляющий животное, не обязан реализовывать свойства, относящиеся к инвентаризации, так как для этого существует отдельный интерфейс `IInventory`.

- **Dependency Inversion:**  
  Высокоуровневые модули (например, `Zoo`) зависят от абстракций (`IVeterinaryClinic`, `IZoo`), а не от конкретных реализаций. DI-контейнер (Microsoft.Extensions.DependencyInjection) используется для внедрения зависимостей, что упрощает тестирование и расширение функционала.
